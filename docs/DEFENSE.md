# 五分钟答辩稿与核心代码讲解

## 0:00–0:35：项目目标与架构

“这是一个面向学校日常教学流程的学生管理系统。它不是单一的信息展示页面，而是把管理员、教师、学生三类角色的权限和业务串成一条闭环。前端使用 Vue 3、TypeScript、Element Plus 和 ECharts；后端使用 Spring Boot 和 MySQL，核心业务服务用 JdbcTemplate 直写清晰的事务 SQL，同时保留 MyBatis-Plus 依赖。Redis 负责真实缓存，通知使用基于 HTTP 长连接的服务端推送 SSE。”

## 0:35–1:20：管理员端

“我先以管理员登录。管理员可以维护学生和教职工账号，查看看板统计，并处理教师提交的成绩。这里演示冻结或重置账号时，后端会在每次请求校验账号状态，因此冻结不是只隐藏页面按钮。看板的课程、成绩分布和院系统计直接来自数据库；Redis 状态也会显示连接、命中和 TTL，Redis 不可用时会明确显示不可用。”

## 1:20–2:05：教师端

“切换到教师后，教师只能管理本人课程。新建课程以后仍可以编辑；点击发布后，课程状态变为已发布并锁定关键课程信息。然后进入成绩录入：可以保存草稿、提交审核。提交不是直接面向学生公开，管理员必须审核通过后才能发布。”

## 2:05–2:50：学生端

“学生登录后只能看到已发布课程。选课时显示容量、时间地点和教师，后端会在事务中再次检查剩余容量和重复选课，所以不能靠前端绕过。成绩发布以前学生查不到成绩；发布以后成绩单显示课程、分数、学分和 GPA。这里还可以展示图片或视频资料预览、天气卡片以及通知实时刷新。”

## 2:50–4:10：核心代码讲解——成绩发布服务

“核心逻辑放在成绩发布服务，而不是只在页面里做计算。服务先校验课程所属、当前成绩状态和审核状态；只有审核通过的课程可以发布。接着在一个事务里锁定成绩和选课记录，对每个学生把分数换算成绩点：60 分及格得到 1.0，每增加 10 分增加一个绩点，最高 4.0；未及格为 0。服务按课程学分计算加权 GPA，并只为尚未结算的记录累计学分。

这段逻辑的关键是幂等性。发布标记和已结算记录在同一事务中更新，第二次执行发布不会再次增加学分。这样即使用户重复点击，或网络重试，也不会产生双倍学分。更新完成后服务发送 refresh 和 notification 事件，在线页面会刷新相关数据。”

## 4:10–5:00：可靠性与验证

“项目将数据库密码和 JWT 密钥留在本机 `.env`，仓库只提供占位示例；Redis 只绑定本机回环地址并使用持久化卷。启动脚本会检查 Redis、MySQL、前后端健康状态。最后运行 smoke 脚本，它用三类账号完整覆盖教师建课发布、学生选课、教师录入提交、管理员审核发布、学生学分查询、重复发布幂等性和越权 403。这个脚本使用时间戳课程码，不会改写演示种子，因此结果可以重复验证。”
