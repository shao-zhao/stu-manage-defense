# 五分钟答辩稿与核心代码讲解

## 0:00–0:35：项目目标与架构

“这是一个面向学校日常教学流程的学生管理系统。管理员、教师、学生三种账号贯穿课程、选课、成绩和通知。前端使用 Vue 3、TypeScript、Element Plus 和 ECharts；后端使用 Spring Boot、MySQL 与 Redis。图表、缓存和通知都读取真实接口，不在页面中生成演示数据。”

## 0:35–1:25：管理员端与技术演示

“管理员可以维护学生和教职工账号，查看统计并审核成绩。进入‘技术演示’，左侧是数据库、Redis、Java 和 Spring Boot 的实际状态；中间连续两次请求 dashboard，展示后端返回的 `hit`、TTL 和顶层 `generatedAt`；下方图表也是第二次真实响应中的课程选课数。Redis 不可用时页面明确显示 DOWN，统计退回数据库读取，不会说缓存仍有效。”

“顶部的‘实时已连接’表示已建立 SSE HTTP 流。保留管理员页面开启，教师提交成绩后，管理员会收到 `notification`，未读角标随之变化。”

## 1:25–2:10：教师端与课程生命周期

“教师新建的课程处于未发布状态，可以完整编辑或删除。发布后进入开放选课；此时课程编号、教师、学分、学时、学期、时间、容量被锁定，只能补充地点、封面和简介。停止选课后，已有选课记录保留；只有满足后端条件的课程才可以恢复选课。前端显示这些限制，但每个接口仍由后端校验所属教师和状态，不能只靠隐藏按钮。”

“教师进入成绩管理，可以保存草稿、提交审核。提交后不能直接对学生公开，管理员审核通过后才能发布。”

## 2:10–2:55：学生端闭环

“学生课程中心只会看到已发布和已停开的课程。已停开课程会解释不能新选课，但已有记录仍保留。选课时页面显示容量、时间、地点和教师；后端事务会再次检查课程状态、容量和重复选课。成绩发布前学生查不到成绩，发布后成绩单才展示分数、学分和 GPA。”

“教学资料支持图片预览和视频播放；教师上传后可发布资料，上传者或管理员才可删除。学生管理页支持模板下载、导入和导出，后端会让包含错误行的导入整体回滚。”

## 2:55–4:10：两段核心代码说明

“第一段是前端统一请求层。`request.ts` 在一个响应拦截器里检查 `{ code: 202, data }` 并返回泛型 data，页面不重复处理信封；Excel 的 blob 下载直接保留二进制。请求拦截器统一增加 Bearer 令牌。路由守卫只是体验，真正的 JWT、账号冻结和角色判断在后端 filter 中完成。”

“第二段是后端事务。`SchoolService.enroll` 锁住选课记录后再检查容量和重复选课，在一个事务里更新选课和课程人数，防止同时抢最后一个名额。`saveGrades` 与 `gradeTransition` 让成绩依次经过草稿、提交、审核、发布；发布事务按学分汇总 GPA，并用已结算标记避免重复发布累加学分。事务成功后才由 EventHub 向对应账号推送 refresh 或 notification。”

## 4:10–5:00：便携运行与问答

“交付版把前端 dist 交给 Spring Boot 同源提供，浏览器访问 `http://127.0.0.1:18090` 即可；开发环境才通过 Vite 代理 `/api` 与 `/static`。同源方式避免生产环境把 API 地址写死为本机开发端口，并支持刷新 `/technology` 这样的深链接。”

常见问答：

- **为什么前端也要做角色菜单？** 减少无关操作；安全仍由后端 JWT filter 和业务服务保证。
- **Redis 失效后数据会错吗？** 不会。相关业务变更删除缓存 key；Redis 不可用时直接查数据库并明确标示状态。
- **为什么 SSE 不把 token 放 URL？** URL 容易被日志和历史记录保存；这里用 fetch 的 Authorization 头传递 Bearer token。
- **如何证明不是模拟数据？** 技术页直接展示 `/api/dashboard` 与 `/api/system/status` 返回值，图表、TTL、生成时间和连接状态都来自运行中的服务。
