# 技术演示与答辩操作说明

本页只描述已实现代码与可观察效果。天气是唯一明确依赖外网的扩展；SSE 是基于 HTTP 长连接的服务端推送。

| 技术点 | 代码位置 | 页面入口与操作 | 预期效果 | 原理与答辩问答 |
|---|---|---|---|---|
| Redis 缓存 | `stu-backend/src/main/java/com/example/stubackend/service/SchoolService.java` 的 dashboard 读取与失效；Redis 配置在 `application.properties` | 管理端“技术演示”页点击缓存读取 | 页面显示真实 `cache.hit`、`ttlSeconds` 和 `generatedAt`。已有缓存时两次都可能命中；等待 TTL 到期或修改课程触发失效后，再读取可观察未命中到命中，命中时生成时间不变而 TTL 下降 | 缓存数据在 Redis 写入后设置 TTL；课程/选课/成绩变更清除相关键，避免展示旧统计。问：为什么不是内存 Map？答：Redis 可被多实例共享并有真实过期策略。 |
| ECharts | `stu-frontend/src/components/AppChart.vue`、`DashboardView.vue`、`TechnologyView.vue` | 首页查看院系学分和成绩分布，技术页悬停课程柱状图 | 显示真实人数、成绩分布及悬停提示；业务变更后重新读取可看到统计变化 | ECharts 负责将 API 数据可视化，统计由后端计算。问：图表是否造数？答：不造数，页面读取 dashboard 接口。 |
| SSE 通知 | `EventHub.java`、`ApiController` 的通知流；`NotificationsView.vue` | 任一已登录管理端保持连接，在技术演示页观察状态；教师提交成绩 | 页面收到 `event:notification`，顶部未读数同步；普通选课只刷新统计，不作为通知触发 | 浏览器用带 Bearer 的 HTTP 流连接；提交事务完成后才推送，断开 emitter 会清理。问：为何不用轮询？答：推送减少空请求并能及时展示状态。 |
| JWT 与路由鉴权 | `JwtAuthFilter.java`、`stu-frontend/src/stores/auth.ts`、`router/index.ts` | 三角色登录、切换页面；冻结账号后继续使用旧 token | 页面按角色导航；后端拒绝越权和冻结 token | 前端用于体验层的路由守卫，后端 filter 才是安全边界；JWT 每次请求解析并检查账号状态。 |
| 事务选课与成绩 | `SchoolService.java` 的选退课、`saveGrades`、成绩状态流 | 教师建课发布；学生选退重选；教师提交；管理员退回、审核、发布 | 容量不超卖；成绩从草稿到发布；重复发布不重复加学分 | 数据库事务把状态和关联记录作为整体提交，选课行锁防并发；成绩按权重算总分，已发布标记保障幂等。 |
| 媒体与 Excel | `ApiController`/`OperationsController`，`MediaView.vue`/`StaffView.vue` | 教师上传 PNG 或视频；管理员下载模板并导入 | 图片可预览，上传者可删除；Excel 错行整体回滚 | 后端验证上传类型和所有者；Excel 在一个事务内校验，任一重复行失败就没有半条新数据。 |
| 天气 API | 前端天气服务及 dashboard 组件 | 有网时打开首页天气卡片；断网后重试 | 有网显示接口返回数据；断网提示不可用 | 外部 HTTP 调用有超时/失败提示，不将天气失败伪装成本地业务故障。 |

## 可直接照做的现场步骤

先启动便携包，普通浏览器登录 `admin`，无痕窗口登录 `teacher01`，密码均为 `123456`。两个角色不要只开同一浏览器的普通标签页，因为这些标签页共享 localStorage 中的登录令牌。学生演示可用另一个浏览器，或最后切换账号。

### Redis：缓存体现在哪里

1. 管理员进入侧栏“技术演示”，确认数据库和 Redis 为 UP。
2. 点击“重新读取”，观察“Redis 两次读取”。这里确实向后端连续请求两次，第二次应显示“命中缓存”。此前首页已请求过统计时，第一次也可能命中，这是正常现象。
3. 记下缓存生成时间和 TTL，隔几秒再次点击。未过期时生成时间不变，TTL 变小，说明使用的是原缓存，而不是重新查数据库再假装命中。
4. 如需展示未命中→命中，停留本页，等待显示的 TTL 过期后再点击。关闭其他自动读取同一管理员统计的页面。
5. 说明课程、选课、成绩变更提交成功后会删除缓存。随后读取会按新数据重建缓存；Redis 暂不可用时仍能查数据库，不会把缓存当成唯一数据源。

对应代码：`ApiController.dashboard` 负责读取、写入和真实 TTL，`SchoolService.after` 在事务提交后清缓存，`CommonConfig.objectMapper` 处理通知时间字段的序列化。评分展示应同时说明 NoSQL 实际用于什么业务，而不只是展示“安装了 Redis”。

### SSE：让通知实际到达

1. 管理员保持页面打开，确认顶部“实时已连接”。
2. 首次演示数据中的“计算机网络”已提交成绩。管理员在成绩管理选择该课程，点击“退回”并填写原因。
3. 无痕窗口的 `teacher01` 打开该课程成绩，刷新后点击“提交审核”。
4. 回到管理员窗口，无需手动刷新，观察通知角标增加，进入通知页查看“成绩待审核”。
5. 管理员审核并发布后，相关学生才能看到成绩。再次演示此流程需新建课程，因为已发布成绩不能退回草稿。

SSE 使用 HTTP 流，不应说成脱离 HTTP 的协议。后端事务提交后才发送事件，避免回滚业务产生成功通知。

### 其他扩展怎么展示

- **ECharts**：首页展示院系学分、成绩分布，技术页展示课程人数；悬停柱形或扇区查看数值，并指出它们来自 `/api/dashboard`。
- **媒体**：教师进入教学资料，选择一张图片或短视频，填写标题并发布；学生查看预览。用实际文件演示，不依赖外链素材。
- **第三方 API**：联网时在首页展示校园天气，说明由后端请求 Open-Meteo；断网时显示不可用，核心教学业务仍可运行。
- **Excel 事务**：管理员下载学生模板，按模板导入；含重复学号或账号的批次整体失败，可对照学生列表证明没有部分导入。

五分钟演示建议以“技术页→教师课程→成绩审核→学生成绩→媒体”为主，详细原理及问答见 [学习路线](LEARNING.md) 和 [演示稿](DEFENSE.md)。教师最终认定哪些扩展计分，以课堂评分要求为准。
